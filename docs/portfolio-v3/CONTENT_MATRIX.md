# Portfolio V3 — Content Matrix

Status: verified-content plan for English-first copy and complete Portuguese parity. This matrix separates facts observed in repositories/public products from claims that still need evidence or privacy approval.

## 1. Editorial rules

1. Lead with the product and engineering problem, not a technology list.
2. Use first person only for contributions that are attributable to Jonathan.
3. Do not infer business impact from technical sophistication.
4. Do not publish traffic, revenue, conversion, user, performance, availability, or delivery metrics without a durable source and explicit approval.
5. “Live” means a public surface was reached during verification; it does not prove every private workflow, provider, or production integration.
6. “Tests exist” means executable test files/scripts were observed. “Tests pass” requires a recorded run from the portfolio rebuild or a clearly attributed project report.
7. State private, local-only, simulated, externally blocked, and incomplete boundaries directly.
8. Professional/client work stays anonymized until the professional inventory and privacy review explicitly approve a stronger label.
9. Screenshots must come from public products, repository assets, or clearly labeled demonstration fixtures. No client data or private operations screens.
10. English and Portuguese copy share the same factual record; translation must never add a claim.

## 10. Known claim corrections for V3

1. **Manual dos Achados automation:** the current V2 says the backend performs trend discovery, clustering, scoring, and marketplace ranking synchronization. Those services were not present in the audited local API checkout. Keep the verified dynamic frontend/Strapi/SEO story and withhold the automation sentence pending evidence.
2. **Manual testing:** test files exist, but many are empty placeholders and no test script is configured. Do not call this an automated test suite.
3. **BuildBalance deployment:** a public API health surface exists; a public frontend was not verified. Do not present a live SaaS UI.
4. **TimeBubble platform:** Expo contains iOS configuration, but the cross-app floating timer implementation is Android-gated. Do not claim iOS feature parity or store release.
5. **Crypto AI:** it is a research/simulation product, not a trading bot, not financial advice, and not evidence of returns.
6. **FebraioTech providers:** repository implementation and the live storefront do not prove every PSP, logistics, fiscal, or ERP provider is currently activated in production.
7. **Repository tests:** presence and prior project reports are not equivalent to a fresh V3 verification run.
